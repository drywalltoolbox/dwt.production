The package exposes 62 skills across agent governance/orchestration, architecture/software systems, frontend/WordPress/integrations, commerce/catalog, marketing/SEO/creative, research/intelligence, product/operations, analytics, QA/security, and documentation. Its strongest reusable architecture is task framing, specialist selection, evidence gathering, ownership checks, implementation, verification, and handoff. DTB already implements these controls in the deterministic registry, roles, workflows, risk flags, reviewers, and AGENTS.md. The project registry stays the router; do not add a principal-agent layer, duplicate capability registry, model-specific doctrine, or plugin-name aliases. UPA skills map to existing DTB roles and skills by subject: engineering and integration to the registered engineering roles; research to `explorer`/`market-intelligence-analyst`; marketing to `marketing-specialist`; SEO, evidence, and commerce claims to current DTB marketing/SEO and domain authorities; governance to `ai-governance-engineer`; verification to the registered reviewers. Plugin evaluations and examples are package-local fixtures, not DTB policy or runtime evidence.

## Precision Product Image Studio 2.4.0

This is an instruction skill, not an image API or persistent generation service. Its important unique contribution is the fail-closed rule for multi-source generation: a prompt or cursor cannot prove that a tool selected the intended original image. The main method and seven reference topics (batch transaction, gallery batch, modes, QA, refinement, source audit, source trace) are consolidated in `.agents/skills/dtb-product-image-engineering/SKILL.md`; the existing product-image art director is now registered as the read-only subject specialist for `product-imagery`. Catalog/media changes remain with catalog/media owners, and UI rendering remains with frontend. Tool use and output claims must match current session capabilities.

## Result and maintenance

Only the high-impact project integrations are added: explicit marketing decision/review routes and an explicit product-imagery route with source-safe guidance. No plugin integration or skill list is treated as a capability grant. Re-audit only when an installed plugin version changes materially or `.agents` routing changes; inspect plugin provenance and current source files before importing further methods.
